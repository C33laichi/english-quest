设计说明书目录中 `3.1.3` 目前是空的（`3.1 系统功能设计` 下只有 `3.1.1 首页模块`、`3.1.2 用户登录模块`）。

作为「拓展功能」的归属口径，避免答辩时被追问"任务书里没有这个模块为什么系统里有"：

```text
听力听写模块属于在任务书既定功能之外自主拓展的模块，其定位是"能力补强"：专升本英语考试包含听力理解题型，而任务书原有的词汇、语法两大主线只覆盖读、写能力。该模块在设计上有两个关键取舍：一是句子的音频资源在构建阶段一次性预生成为静态文件（共150条，约3.3MB），随前端一起发布，因此运行时不需要任何外部语音服务，断网环境也能正常播放；二是听写答案即英文原句本身，若改用浏览器实时语音合成，就必须把原句文本下发到前端，答案会暴露在网络响应中，"无提示模式"将失去意义，所以采用预生成音频后，前端只拿到音频、拿不到文本，从而保证听写成绩的真实性。
```

## 五、本次为对齐任务书所做的系统改动（供写说明书/答辩时对照）

任务书原定的**登录注册模块**要求"学生、管理员的注册"，**后台管理模块**要求对"用户、题库、关卡等数据的添加、查询、修改、删除"。
原系统在这两处存在缺口，现已补齐（后端已重新打包、前端已重新构建，并已通过接口实测）：

| 任务书条款 | 原缺口 | 本次改动 | 实测结果 |
| --- | --- | --- | --- |
| 登录注册模块：学生、**管理员**的注册 | 公开注册接口把角色写死为 `STUDENT`，后台也没有"新增用户"入口，管理员账号只能靠 SQL 手工插入 | 新增 `POST /api/admin/users`，后台「用户管理」增加"新增用户"按钮，可指定角色为 学生/管理员；非法角色直接拒绝 | 新增学生 ✓、新增管理员 ✓、非法角色返回"角色只能是 STUDENT 或 ADMIN" ✓ |
| 后台管理模块：关卡等数据的添加、查询、修改、**删除** | 只有关卡的"增/改/查"，没有"删"；词汇关卡的上层接口虽在，但前端没有任何入口 | 新增 `DELETE /api/admin/vocab/levels/{id}` 与 `DELETE /api/admin/grammar/lessons/{id}`；「词汇题库」页增加"关卡管理"（可增删改关卡），「语法题库」页增加"新增 Day"与删除关卡 | 删除有题目的词汇关卡被拒（"该关卡下还有 40 道题目，请先删除题目再删关卡"）✓；删除空关卡成功 ✓；删除语法中间 Day 被拒（"后面还有 14 天，只能从最后一天开始删"）✓；删除最后一个 Day 成功 ✓ |

> 两处删除都带了安全校验：有题目或有学生作答记录时不允许删；
> 语法关卡因为有"按日解锁"的链式依赖，只允许从最后一天往前删，否则后面的关卡会因为缺前序而永久锁死。
> 答辩时把这两条校验讲出来，比单纯"能删了"更有说服力。

### 关于"调用大语言模型 API"这一句的实际口径（★ 已按"本地生成、未配 Key"定稿）

任务书原文写的是"**调用大语言模型API**生成同题型练习题"，而系统当前**没有配置 API Key**，
四项 AI 能力全部走**本地离线生成**（`source=MOCK`，一次网络请求都不发，25 项守护检查全过）。

为了让任务书与系统实际行为一致，**建议把任务书里那一句改成下面的写法**（二选一）：

**① 推荐写法（完整，替换"错题本与AI智能练习模块"整句）**

```text
错题本与AI智能练习模块：在该模块中完成了错题自动收录、错题重练，以及基于大语言模型的智能练习生成功能；生成服务采用"在线接口优先、本地生成兜底"的双通道设计，在配置了大模型API密钥且网络可用时通过兼容OpenAI协议的接口在线生成，未配置密钥或调用失败时自动降级为本地离线生成，生成内容真实可用而非占位符，保证断网、无密钥环境下各项智能功能仍可完整使用。
```

**② 精简写法（只把"调用大语言模型API生成同题型练习题"这一小段替换掉）**

```text
基于大语言模型的智能练习生成功能（配置API密钥时在线调用大语言模型，未配置时自动降级为本地离线生成）
```

> **★ 提醒：以后如果配了 API Key，记得回来改这里**
>
> 现在的写法是"**本地生成**"口径，与当前 `api-key: ${AI_API_KEY:}`（留空）一致。
> 如果之后你在环境变量里配了 `AI_API_KEY` 并重启后端（`set AI_API_KEY=sk-xxxx` 后重新 `java -jar`），
> 系统就会真的在线调用 DeepSeek，此时：
> 1. 上面的①/②要把"未配置时自动降级为本地离线生成"改成"调用大语言模型API在线生成"；
> 2. 同时删掉 jar 里的旧配置再重新打包（`mvn package -DskipTests`），否则改了源码也不生效；
> 3. **交付前务必全项目搜一遍密钥残留**：`grep -rn "sk-[A-Za-z0-9]\{20,\}" .`，
>    明文 Key 一旦打进 jar 就跟着压缩包一起送出去了。
>
> 判断当前到底走哪条路，跑一下就能确认：
> `node scripts/ai_local_mode_check.mjs` —— `source=MOCK` 表示没联网（本地生成），`LLM` 表示真调了接口。
